# Накопление значений отчёта в рамках периода — дизайн

Дата: 2026-10-21

## Проблема

Экран «Отчёт» ([report_editor_screen.dart](../../../lib/screens/report/report_editor_screen.dart)) загружает сохранённые значения за выбранный период, а при сохранении `upsertReport` полностью перезаписывает их. Если пользователь заполнил отчёт 02.09, а 05.09 вносит новые значения за тот же период, прежние значения теряются.

## Цель

Новые значения прибавляются к уже сохранённым в рамках выбранного периода. На карточке видна накопленная сумма за период.

Требования:
1. Суммирование только в рамках выбранного периода (`periodId`).
2. Данные других периодов не учитываются.
3. Ранее сохранённые значения сохраняются и участвуют в расчёте.
4. При повторном открытии виден актуальный итог за период.
5. Повторное сохранение без новых данных не прибавляет ничего.

## Решение

Сложение выполняется в приложении: перед сохранением отчёт за период перечитывается из базы, к свежему итогу прибавляются введённые добавки, затем используется существующий `upsertReport`. Изменения на сервере не нужны.

Известное ограничение: при одновременном сохранении с двух устройств одно прибавление может потеряться. Для личного отчёта одного пользователя это приемлемо.

### Состояние редактора

- `_report` — сохранённые итоги за выбранный период (из базы). В UI только читается.
- `_deltas: Map<String, int>` — сколько прибавить к каждому показателю. Сбрасывается в пустую карту при загрузке экрана, смене периода и после успешного сохранения.

### Карточка показателя

- Бейдж справа — итог за период, например `13 стр.`. Если `итог + добавка` больше максимума, рядом бейдж `+N` (превышение), как сейчас.
- Подпись «Добавить» над элементами ввода.
- Слайдер, кнопка «+», ручной ввод и быстрые кнопки (3/5/8/10) задают добавку. Слайдер — от 0 до максимума; при отрицательной добавке стоит на 0. Ручной ввод может задать добавку больше максимума (как сейчас для значения).
- Кнопка «−» уменьшает добавку, в том числе ниже 0, но не ниже `−итог` (итог не может стать отрицательным). Центральное поле показывает добавку со знаком, например `−2`.
- Пока добавка не равна 0, под бейджем — предпросмотр «станет: 18».

### Сохранение

1. Если все добавки равны 0 — в базу ничего не пишется, показывается сообщение «Нет новых данных».
2. Иначе:
   - перечитать отчёт за `_selectedPeriod` (`getReportByPeriod`);
   - для каждого показателя с ненулевой добавкой: `итог = max(0, свежий итог + добавка)`; остальные показатели берутся из свежего отчёта без изменений;
   - сохранить через `upsertReport`;
   - `_report` = сохранённый отчёт, `_deltas` очищается, сообщение «Отчёт сохранён».
3. При ошибке добавки остаются на экране, итог не меняется — пользователь может повторить.

Вычисление нового итога — чистая функция `applyReportDeltas(Map<String, int> totals, Map<String, int> deltas) → Map<String, int>`.

### Фоновая перезагрузка

`_reloadPeriods` (при возврате приложения на передний план) обновляет `_report`. Если выбранный период не изменился, `_deltas` не сбрасываются; если период сменился (например, был удалён), `_deltas` сбрасываются.

## Тестирование

- Юнит-тесты `applyReportDeltas`: обычное сложение; отрицательная добавка; нижняя граница 0; пустые/нулевые добавки не меняют итог; показатели без добавки сохраняются.
- Ручная проверка на устройстве: сохранить, закрыть, открыть тот же период, добавить, сохранить — итог равен сумме; другой период не изменился; повторное сохранение без изменений не меняет итог.

## Вне рамок

- Серверное атомарное сложение (RPC).
- История отдельных записей (кто/когда сколько добавил).
